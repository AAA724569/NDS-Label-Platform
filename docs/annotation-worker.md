## 选帧与结果

- 文件名含可解析拍摄时间时按它排序，否则使用库内采集时间，确保可回溯的稳定顺序。
- 累积有效视频时长，在约1/6、1/2、5/6处抽候选帧；选择可辨认道路结构的帧，保留原图和1920像素以内模型输入。
- 清晰度不以白天亮度作为筛选条件；不可读或解码失败候选有其他可读视频回退。
- 时间未知时只用 ffprobe 获取真实媒体时长用于选帧，不用文件大小估算，不修改原视频表。
- 默认每批次一张图片一次模型调用；每个字段固定范围 frame，结果保持 pending。
- 原始模型响应存在内部数据库和私有缓存；JSON语法、27字段、枚举、单多选、未知原因和测量限制全部通过才算 completed。
- 单帧不具备几何标定和气温传感信息，坡度/横坡/宽度/气温保持未知。
- 图片以内容哈希命名，重新抽帧不覆盖已审核证据；最终入库比较证据修订号，人工修改或审核优先保留。

## 后台配置与控制

私有配置 `/home/stu1/.config/nds-annotation-worker.env`，权限0600，仅存服务所需写入/只读连接和模型密钥；
凭据不进入Git、日志、网页或模型提示词。图片和缓存位于 `/home/stu1/.local/share/nds-annotations`，仅内网服务账号访问。
服务程序位于当前已附加的 annotation-schema worktree，服务依赖此目录，运行期间保持它可用。

```bash
systemctl --user status nds-annotation-worker.service
systemctl --user stop nds-annotation-worker.service
systemctl --user start nds-annotation-worker.service
journalctl --user -u nds-annotation-worker.service -n 20 --no-pager
```

已启用随用户服务启动，user lingering 为 yes，关闭终端不影响队列。
单进程数据库锁避免重复启动；异常中断续跑，缓存命中相同帧及提示词版本时复用响应。
每批最多3次尝试；临时网络或限流问题有限重试。401/402停止队列，修复私有配置/额度后由维护人员重启。
校验失败不会自动付费重试，保留原因供人工处理。
每5分钟发现新采集文件夹，既有已完成/已审核结果不会被定时发现重复调用模型。
